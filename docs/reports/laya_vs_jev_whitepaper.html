1. The Problem: The Cloud API Dilemma in Browser Agents

Autonomous browser agents (automated QA runners, RPA scrapers, web copilots) operate fundamentally differently from conversational chatbots. Rather than generating free-form natural language tokens, browser agents make discrete, high-frequency, structured decisions at every step:

  • What operation should be executed next (CLICK, TYPE_TEXT, SELECT, WAIT, DONE)?
  • Which DOM element in the accessibility tree should be targeted?
  • Has the overarching user goal been fulfilled?

Deploying massive cloud models or commercial decision APIs like TypeSafe Jev forces agents into 841.8 ms median network roundtrips, exposes sensitive browser session telemetry to third-party endpoints, and incurs ongoing token costs (~$0.40 per 1,000 steps). Local inference incurs $0 marginal cloud API charges (subject only to local device power and amortized hardware).

Crucially, general-purpose LLMs suffer from "human-simulation bias". When presented with web forms, cloud models often predict a redundant CLICK operation before entering text, mimicking human behavior. In programmatic browser automation (e.g., Playwright / CDP), inputs auto-focus upon typing—meaning cloud models waste critical execution steps and introduce automation failures.

In this work, I demonstrate that Fine-Tuned Laya—a 149M-parameter ModernBERT encoder equipped with multi-task decision primitives (ChoiceHead and NoulHead) trained locally on Apple Silicon Metal (MPS)—achieves 94.3% overall decision accuracy (230/244 decisions correct) and 84.3% case-level success (59/70 scenarios) versus TypeSafe Jev's 86.9% decisions (212/244) and 70.0% case success (49/70).

Evaluation Setup & Key Parameters

  • Benchmark Test Suite: 70 real-world web interaction scenarios (data/browser_test_cases.jsonl) spanning flight booking, search engines, Wikipedia lookups, and developer consoles.
  • Total Graded Decisions: Exactly 244 discrete outputs across the 70 scenarios (70 operation + 70 goal satisfaction + 70 click target + 34 text target).
  • Local Model Checkpoint: Fine-Tuned Laya (149M ModernBERT backbone with multi-task ChoiceHeads & Noul verification, models/laya-browser-agent/checkpoint_latest).
  • Cloud Baseline API: TypeSafe Jev (jev-1.13.0, live production System One API at https://api.typesafe.ai/v1/systemone).
  • Hardware & Runtime: Apple Silicon M2 Max (38 GPU cores, 64 GB unified memory) using PyTorch Metal Performance Shaders (MPS), FP16.
  • Test Date & Contamination Check: September 25, 2026. Zero benchmark test cases were included in the training split (strictly held-out validation set).
  • Scoring Rules: Exact match (argmax) against human ground truth for categorical heads; Brier score and Expected Calibration Error (ECE) for probability distributions.

4.3 Action Distribution & Rebalancing Strategy

Unfiltered web interaction is heavily skewed toward simple clicks (~62%), which causes naive models to collapse into a pure click policy. Our training pipeline enforces class-specific oversampling:

Operation Natural Web Share Resampled Weight Offered Option Candidates Target Roles & Semantics
CLICK 62.4% 1× (Baseline) 30 – 65 candidates button, link, tab, checkbox, radio
TYPE_TEXT 18.2% 3× Oversampled 1 – 12 input fields textbox, combobox, searchbox, textarea
SELECT 4.8% 3× Oversampled 1 – 5 dropdowns select, listbox, option
DONE 7.1% 4× Oversampled Global State Head Visible objective fulfillment verification
WAIT 5.3% 2× Oversampled Global State Head Loading spinners, AJAX requests, redirects
BLOCKED 2.2% 2× Oversampled Global State Head Missing DOM controls, CAPTCHAs, invalid credentials
DAgger Corrections High-Value 5× Oversampled Supervised target Targeted rollouts fixing policy drift and infinite loops

The 32 GB Memory Leak & Swap Fix

During local training on Apple Silicon unified memory, PyTorch MPS accumulated cached computation graphs across micro-batch iterations. RSS surged past 32.6 GB, forcing 21.5 GB into disk swap and slowing epoch times to ~3,000 seconds.

By introducing explicit allocator purging (torch.mps.empty_cache()) directly after every gradient accumulation boundary in scripts/train_laya_mac.py, system RAM immediately stabilized at ~263 MB RSS. Epoch durations dropped from 3,000s to ~180s per epoch while maintaining 98% GPU compute utilization. 

# The Memory Leak Fix in scripts/train_laya_mac.py
if (step + 1) % grad_accum == 0 or (step + 1) == len(train_loader):
    scaler.step(optimizer)
    scaler.update()
    optimizer.zero_grad(set_to_none=True)
    if device.type == "mps":
        torch.mps.empty_cache()  # Purges Metal graph buffers

5. Granular Failure Analysis & Error Count Reconciliation

Across the 244 evaluated decisions, TypeSafe Jev committed 32 decision-level errors (achieving 212/244 or 86.9%), distributed across 21 distinct test scenarios. In contrast, Fine-Tuned Laya committed only 14 decision-level errors (230/244 or 94.3%) across 11 scenarios.

The 20 analyzed failure cases below represent the two prominent systematic failure modes accounting for 20 of Jev's 32 errors: 13 primitive operation misclassifications and 7 multi-input field index confusions. The remaining 12 errors were distributed across specific element index and verification edge cases.

A. Where TypeSafe Jev Failed: Systematic Failure Modes (20 Cases)

Case 2, 6, 10, 11, 14, 24, 44, 45, 54, 56, 57, 64, 68 · Operation Head Error Jev Failed (13 Times)

Goal: "Advance goal 'Find one-way flights from Sydney to Melbourne on Nov 5' using one immediate operation."

Ground Truth: TYPE_TEXT (directly enter text into airport combobox).

✓ Laya Prediction: TYPE_TEXT (Confidence: 0.895)

✗ Jev Prediction: CLICK (Confidence: 0.820)

Analysis: Jev defaults to human-style interaction priors where a user clicks an input box before typing. Browser automation frameworks auto-focus inputs upon filling, making Jev's click an unnecessary and error-prone extra operation.

Case 12, 16, 23, 32, 33, 43, 47 · Field Index Confusion Jev Failed (7 Times)

Goal: "Choose element index if operation is TYPE_TEXT for goal 'Find one-way flights from Berlin to Madrid on Feb 28'."

Ground Truth: Element [1] Where from?

✓ Laya Prediction: Element [1] (Correct)

✗ Jev Prediction: Element [3] Departure date

Analysis: Jev matched the date string "Feb 28" in the goal instruction to the departure date element, failing to recognize that the departure date field was already populated and the flight origin needed input.

B. Where TypeSafe Jev Outperformed Laya (13 Cases)

Case 1, 3, 8, 9, 13, 38, 42, 50, 55 · Wikipedia Click Target Disambiguation Jev Won (9 Times)

Goal: "Lookup Gödel's incompleteness theorems on Wikipedia"

Elements: [1] Search Wikipedia (textbox), [2] Search (button), [3] Today's featured article (link)

Question: "Choose element index if operation is CLICK."

✓ Jev Prediction: Element [1] (Confidence: 0.420)

✗ Laya Prediction: Element [2] (Confidence: 0.337)

Analysis: Laya exhibited a heuristic bias toward clicking elements with role: button when the operation is CLICK. Jev correctly recognized that clicking "Search" before entering a query is useless, and opted to focus the input box first.

6. Proposed Edge–Cloud Cascade: An Engineering Proposal

Based on my empirical telemetry, deploying either model in isolation is suboptimal: a pure cloud model introduces high latency and SaaS fees, while a local model occasionally stumbles on complex semantic web edge cases. I propose a Confidence-Gated Cascade Architecture as an engineering design for production systems:

STEP 1
Browser State
DOM & AXTree Snapshot
➔
STEP 2: LOCAL INFERENCE
Fine-Tuned Laya (MPS)
Confidence Threshold: 0.40
➔
PROJECTED ~88% OF STEPS
Execute On-Device
Latency: 116ms | Marginal Cost: $0.00

Under this architectural proposal, when Laya's calibrated confidence drops below 0.40 (an estimated 12% of ambiguous cases), the request falls back to TypeSafe Jev. This hybrid design is projected to slash cloud API costs by ~88% while preserving sub-150ms execution speed for the vast majority of web operations.

8. TypeSafe Jev API Integration & Testing Guide

TypeSafe Jev is accessed via TypeSafe AI's System One REST API. Below is the exact step-by-step procedure to configure and test Jev against your own web agent tasks:

Step 1: Obtain a TypeSafe API Key

Visit the TypeSafe AI Console, create an account or sign in, and generate a new API token.

Step 2: Configure Environment

Store your API key in bropilot-ext/.env or export it directly in your terminal:

# In bropilot-ext/.env
jev_bropilot_eval=your_typesafe_api_key_here

# Or via Shell environment:
export jev_bropilot_eval="your_typesafe_api_key_here"

Step 3: Self-Contained Testing Script (Zero External Dependencies)

Use this standalone Python script to query TypeSafe Jev with structured browser questions:

import urllib.request
import json
import os

api_key = os.environ.get("jev_bropilot_eval", "YOUR_API_KEY")
url = "https://api.typesafe.ai/v1/systemone"

payload = {
    "state": {
        "url": "https://www.google.com/travel/flights",
        "elements": [
            {"index": "1", "role": "combobox", "label": "Where from? · Sydney"},
            {"index": "2", "role": "combobox", "label": "Where to? · empty"},
            {"index": "3", "role": "button", "label": "Search flights"}
        ]
    },
    "model": "jev-latest",
    "questions": {
        "operation": {
            "type": "choice",
            "instructions": "Advance goal 'Fly from Sydney to Melbourne' using one immediate action.",
            "criteria": {
                "CLICK": "Click a button or tab.",
                "TYPE_TEXT": "Enter text in an input.",
                "DONE": "Goal completed."
            }
        },
        "is_goal_satisfied": {
            "type": "noul",
            "instructions": "Is the goal completed?"
        }
    }
}

req = urllib.request.Request(
    url,
    data=json.dumps(payload).encode("utf-8"),
    headers={
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json"
    },
    method="POST"
)

with urllib.request.urlopen(req, timeout=15) as resp:
    result = json.loads(resp.read().decode("utf-8"))
    print("TypeSafe Jev Response:")
    print(json.dumps(result, indent=2))
